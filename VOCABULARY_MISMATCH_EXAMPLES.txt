EXAMPLE 1: CEILING HEIGHT
================================================================================

TEMPLATE VOCABULARY (Template ID: AX4)
--------------------------------------
Template name: "Spatial Enclosure and Attention Capacity"
Causal link:
  from_entity: "ceiling_height"
  from_level: "environmental"
  to_entity: "directed_attention"
  to_level: "cognitive"

EXTRACTION FILE (10.1016_j.healthplace.2012.01.012.json)
-------------------------------------------------------
Claim:
  antecedent: "Rooms with high ceilings (3.8m) vs. low ceilings (2.4m)"
  consequent: "Improved directed attention and task completion rates"

Raw tokens: {rooms, high, ceilings, improved, directed, attention, task, completion}
Mechanism overlap with template: {ceiling, attention}
↓ MATCHES (86.9% raw text mode)

DATABASE RECORD (beliefs table)
-------------------------------
belief_id: "pdf:doi:10.1016_j.healthplace..."
environment_id: "env.ae.high_ceiling"
outcome_id: "out.cog.attention"
content: "Rooms with high ceilings (3.8m) vs. low ceilings (2.4m) - 
          improved directed attention and task completion"

Template matcher process:
  1. Load environment_id: "env.ae.high_ceiling"
  2. Normalize: "env.ae.high_ceiling" → "env_ae_high_ceiling"
  3. Tokenize: {env, ae, high, ceiling}
  4. Compare to template input_terms: {ceiling_height}
  5. Check for overlap: "ceiling" (substring) appears in both
  6. But ENV_BRIDGES doesn't have rule for "env_ae_high_ceiling"
  7. No match found in bridge logic
  8. Score: 0.0 unless fallback to content
  ↓ NO MATCH (29.9% DB field mode)

VOCABULARY GAP
--------------
Template expects:   ceiling_height
Database has:       env.ae.high_ceiling

Semantic alignment: HIGH (both refer to ceiling height)
Lexical alignment:  LOW ("ceiling_height" vs "env_ae_high_ceiling")
Bridge coverage:    NO (ENV_BRIDGES only has 21 total mappings)

What's missing: A mapping from "env.ae.high_ceiling" → "ceiling_height"
                OR from raw antecedent "high ceilings" → template input_term

SUMMARY OF MISMATCHES
================================================================================

Pattern 1: Hierarchical vs. Flat
  Template: "ceiling_height" (flat, domain-specific term)
  Database: "env.ae.high_ceiling" (hierarchical with prefix)
  → Namespace "env.ae" loses semantic meaning

Pattern 2: Domain Specificity
  Template: "aesthetic_emotion" (specific psychological construct)
  Database: "out.affect.mood" (general domain category)
  → Database loses specificity; multiple outcomes map to same outcome_id

Pattern 3: Bridge Key Mismatch
  Template: ENV_BRIDGES["ambient_noise_dba"] = {...}
  Database: "env.acoustic.ambient_noise_level"
  → Bridge keys assume different DB structure than actual

Pattern 4: Multiple Outcome Levels
  Database has: "out.affect.mood", "out.affect.mood.positive", "out.affect.mood.negative"
  Template expects: Single outcome term for all variants
  → Hierarchy not accounted for in template vocabulary

Pattern 5: Natural Language vs. Canonical
  Extraction: "high ceilings with daylighting"
  Template: mechanism_terms extracted from description
  Database: "env.ae.high_ceiling|env.ae.daylighting"
  → Three different representations for same concept

SOLUTION: Create mapping layer
  Raw text → Normalize → Map to canonical ID → Store → Template match
         ↑
    [NEW STEP]
    environment_id_normalizer
    outcome_id_normalizer
