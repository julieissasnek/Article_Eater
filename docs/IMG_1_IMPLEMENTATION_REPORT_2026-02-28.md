### 1. Batch Orchestration Script

**File**: `/scripts/run_image_extraction_batch.py`
**Lines of code**: 280
**Language**: Python 3
**Dependencies**: PyMuPDF (fitz) for extraction; standard library for orchestration

#### Features

- **Batch extraction**: Process all 56 articles in single command
- **PDF discovery**: Search across multiple source locations
  - Primary: `data/pdfs/` (local project)
  - Secondary: `/Users/davidusa/REPOS/Article_Finder_v3_2_3/data/pdfs/` (Article_Finder)
- **Dry-run mode**: Validate PDFs without extraction
- **Error handling**: Graceful failures with detailed error classification
- **Manifest generation**: Complete metadata capture per image
- **Reporting**: Human-readable extraction reports

#### Usage

```bash
# Validate PDF availability
python scripts/run_image_extraction_batch.py --validate-pdfs

# Dry-run (validate without extracting)
python scripts/run_image_extraction_batch.py --dry-run

# Full extraction (requires PyMuPDF installed)
python scripts/run_image_extraction_batch.py --extract

# Print report from existing manifest
python scripts/run_image_extraction_batch.py --report
```

#### Data Classes

Defined three main data structures:

1. **ExtractionResult**: Per-article extraction outcome
   - DOI, PDF path, success flag
   - Images extracted count and metadata
   - Extraction time, error messages

2. **ExtractionManifest**: Complete batch outcome
   - Extraction date and version
   - Summary statistics (total, processed, successful, failed)
   - Per-article results and PDF not-found list
   - Error classification by type

3. **ImageMetadata** (nested): Per-image details
   - Page number, image index on page
   - Dimensions (width, height)
   - File size in bytes
   - Colorspace (RGB, CMYK, etc.)
   - File extension

## Phase 2: PDF Acquisition Strategy

### Problem Statement

56 articles identified as HIGH-priority for image extraction. All flagged `has_pdf: true` in figure scan, but PDFs not available in local filesystem. Cannot proceed to Phase 3 (extraction) without PDFs.

### Acquisition Methods

#### Option A: Article_Finder Integration (Recommended)

**Method**: Use Article_Finder's PDF acquisition system
**Pros**:
- Already familiar system (used by project)
- Handles authentication, rate limiting, deduplication
- Integrates with existing metadata (S2, CrossRef enrichment)

**Cons**:
- Requires Article_Finder repository to be accessible
- May require network/institutional access for paywalled articles
- Rate limits may slow batch download

**Steps**:
1. Identify Article_Finder's PDF downloader component
2. Batch request all 56 DOIs
3. Download to `/Users/davidusa/REPOS/Article_Finder_v3_2_3/data/pdfs/`
4. Symlink or copy to local `data/pdfs/`

**Estimated time**: 2–3 hours

#### Option B: CrossRef/Unpaywall API

**Method**: Query Unpaywall API for OA PDFs
**Pros**:
- ~78% of academic papers now have OA versions
- Free, fast, no authentication required
- Simple REST API

**Cons**:
- No paywalled articles (limited coverage for highly specialized journals)
- May return lower-quality scans
- Requires fallback method for missing papers

**Implementation**:
```python
import requests
import json

# Example: Fetch OA PDF for one DOI
doi = "10.1007/s00530-024-01514-6"
url = f"https://api.unpaywall.org/v2/{doi}?email=user@example.com"
resp = requests.get(url)
data = resp.json()

if data.get("is_oa") and data.get("best_oa_location"):
    pdf_url = data["best_oa_location"]["url"]
    # Download PDF
```

**Estimated time**: 1–2 hours (batch script)

#### Option C: Manual Download

**Method**: Download from journal websites one-by-one
**Pros**:
- Guaranteed access (if article exists)
- Highest quality PDFs

**Cons**:
- Very time-consuming (4–6 hours for 56 articles)
- Requires manual authentication for each journal
- Prone to human error

**Estimated time**: 4–6 hours

#### Option D: Hybrid Approach (Most Pragmatic)

**Steps**:
1. Try Article_Finder first (fastest if available)
2. Fall back to Unpaywall API (covers ~78% OA)
3. Manual download for remaining highly-cited papers (if any)

**Estimated time**: 2–3 hours total

### Recommended Action

**Recommendation**: Option A (Article_Finder) as primary, Option B (Unpaywall) as fallback

**Timeline**: Complete PDF acquisition within 3 hours

## Appendix B: Script Architecture

### Main Functions

1. **`load_high_priority_articles()`**
   - Loads `data/figure_scan/high_priority_articles.json`
   - Returns list of 56 article dicts

2. **`find_pdf(doi: str) -> Optional[Path]`**
   - Searches across multiple source locations
   - Returns Path if found, None otherwise

3. **`extract_images_from_pdf(pdf_path, output_dir, doi, min_size=5000) -> dict`**
   - Uses PyMuPDF (fitz) to extract images
   - Filters by size (>5KB to exclude UI elements)
   - Returns structured result dict

4. **`validate_pdfs(dry_run=False) -> dict`**
   - Validates PDF availability
   - Returns availability statistics

5. **`run_extraction_batch(dry_run=False) -> ExtractionManifest`**
   - Main orchestration function
   - Processes all 56 articles
   - Returns manifest object

6. **`save_extraction_manifest(manifest)`**
   - Serializes manifest to JSON
   - Writes to `data/image_pool/extraction_manifest.json`

7. **`print_extraction_report(manifest)`**
   - Human-readable report output
   - Summary stats, errors, results

### Error Classification

errors_by_type = {
